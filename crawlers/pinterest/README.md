# Pinterest 图集 · pinterest-dl

平台当前使用本地 `pinterest-dl` 项目作为 Pinterest API 采集引擎。源码从 `D:/我的学习文件/爬虫/pinterest-dl` 复制到 `vendor/pinterest-dl/`，导入时优先加载内置源码；原项目保持原样。上游为 [sean1832/pinterest-dl](https://github.com/sean1832/pinterest-dl)，Apache 2.0 许可及原说明保留在内置目录。

## 使用

在 SpiderRoom 根目录运行 `python -m pip install -r requirements.txt`，然后双击 `start.bat`。选择「Pinterest 图集」，输入区分为「单个 Pin」「整块画板」「画板分区」「用户主页」「分享短链接」「关键词搜索」，每类都有示例和采集范围说明，每行一个目标。Pin 支持数字 ID，主页支持用户名，短链接支持完整 pin.it 地址。多个分类可同时填写，开始采集时统一提交；说明会汇总已填写数量。保存和重新打开时，已有链接自动归入对应类别。

填写保存目录和图片上限后开始采集。Cookie 点击「保存设置」后按工具保存在本机，重启或失败后仍会回填；公开内容可留空。高级设置支持 HTTP / HTTPS / SOCKS5 代理、超时、重试、并发、页面上限、最小宽高、单图大小和内容去重。浏览器设置用于接口失败后的页面回退。

图片数量按每条输入链接计算，主页下所有画板共享该条链接的额度；成功下载和已存在图片占额度，失败、过滤和内容重复不占。0 表示数量不限，仍受每个列表页数限制。关闭「包含画板分区」会过滤画板主列表中的分区图片，直接输入分区链接仍采集该分区。

原生目录选择、实时进度、日志、运行记录、图片预览、长边缩放和底部裁剪继续使用。图片组织和索引保持兼容，已有下载目录及配置不迁移。关闭缩放且裁剪为 0 时保留原图字节，更改参数会生成新版本。

## 接入方式

- `backend.py` 优先导入内置源码，避免系统同名包覆盖指定项目。
- `engine.py` 使用 pinterest-dl 的 `Api`、`PinResponse`、请求构建器及 `PinterestDL.with_api().scrape()`；Pin 固定请求 1 个且核对 Pin ID，避免上游默认追加相关图片。
- 画板和分区直接调用上游 API 方法；平台负责有界分页、重复游标终止、有效图片额度和原始响应中的候选图片提取。主页画板枚举补充使用相同的上游请求构建器。
- 将上游会话适配到平台请求层，统一 Cookie、代理、超时、HTTP 错误、重试、限速和停止检查。禁用上游无超时的默认 Cookie 获取，避免初始化阻塞。
- 下载复用平台的流式验证、原图候选回退、内容哈希、临时文件及索引，以保留平台裁剪、命名、预览和已有图片跳过行为。`.sources.jsonl` 记录 Pin 来源和实际图片尺寸。
- 接口异常时尝试已有页面 / 浏览器恢复，只使用剩余页面额度。停止仍由停止文件通知，超时由平台结束进程树。

输入区也提供「关键词搜索」：每行一个词，支持中文、英文及含特殊字符的词，也可粘贴 `https://www.pinterest.com/search/pins/?q=…`。关键词与其他分类可同时采集，每个关键词独立计算图片上限，输出在「关键词搜索」目录下按词分组。保存后刷新会恢复原始关键词，搜索使用上游 `Api.get_search()` 并受相同分页、代理、Cookie、去重和图片处理约束；搜索受限时请检查 Cookie / 网络。

当前平台保持图片及视频封面的范围；上游的视频文件、相似图片和元数据写入未新增为平台功能。

## 独立 CLI

在平台根目录执行：

```powershell
python -m crawlers.pinterest "https://www.pinterest.com/pinterest/girls-night-in/" --count 2 --output "D:/Pictures/Pinterest"
```

可选 `--proxy`、`--show-browser`、`--config`、`--cookie-file`。CLI 输出平台兼容的 JSON 事件。
